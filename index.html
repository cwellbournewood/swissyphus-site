The rollup

66 public sources.
One MCP server.

Swiss public data is excellent and scattered: every office runs its own API, formats, languages, coordinate system and licence. Sources change, move and go down; Swissyphus keeps them in one interface, every day, automatically, so your agent never has to.

01→

Gather

Always running. Allowlisted public hosts only. Cached, rate-limit aware with circuit breakers, and when a source goes down you get the last good answer, clearly marked stale.

02→

Roll up

45 connector modules turn formats, languages and LV95 ↔ WGS84 into 151 typed tools. One schema serves MCP and REST, so the two never drift.

66

sources in one boulder: one server, one install, zero keys.

03

Deliver

Every answer carries its source envelope: publisher, licence, attribution, the publisher’s own timestamp, cache status and the exact upstream requests behind it.

Provenance

Every answer cited.

Every one of the 151 tools returns the same envelope: who publishes the data, under which licence, the attribution to show, the publisher’s own timestamp (null when it publishes none, never the fetch time in disguise), cache status, and the exact upstream requests behind the answer. Credentials are always redacted.

MIT for the software. The data keeps its own licences, and every response tells you which one.

The licence register for all 66 sources is one call away: list_sources.

A hosted preset leaves out data whose terms forbid redistribution.

Two surfaces · one schema

MCP and REST.
Same 151 tools.

01 — MCP, for agents

stdio locally, Streamable HTTP when hosted. Every tool registers with a JSON schema, so Claude, Cursor, VS Code and any MCP client discover them without configuration. Short on context? --preset discovery keeps 7 tools loaded and still reaches all of them.

→ tools/list
← 151 tools with input schemas
→ tools/call get_avalanche_danger_at { lat: 46.8, lon: 9.8 }
← data + source envelope · © SLF

02 — REST, for everything else

Plain HTTP and JSON for scripts, apps and cron. GET with query parameters, POST with a body, an OpenAPI 3.1 spec generated from the same tool schemas, and a remote MCP endpoint on the same port.

GET  /v1/tools/get_weather?plz=8001
POST /v1/tools/compare_electricity_tariffs
GET  /v1/health/sources
GET  /openapi.json
