Setup · under 60 seconds to first result

Roll it into
your client.

Swissyphus runs locally through npx: nothing to install globally, nothing to sign up for, no keys. You need Node.js 20 or newer. Pick your client below; the config is the same shape everywhere.

Quick start

01

Add it to your client

Register it once with Claude Code, or paste the config below into any MCP client.

$claude mcp add --scope user swissyphus -- npx -y swissyphus
02

Check the sources

The doctor probes every upstream source and prints its status and latency.

$npx -y swissyphus doctor

Ask Switzerland

Your agent now sees all 151 tools, plus three ready-made prompts.

Presets

        
Roll up only
what you need.

      

      
151 tool definitions cost about 36k tokens of context. Add --preset or --modules to any command; they combine. Or build a custom set on the modules page.

    

    


$ npx -y swissyphus --modules transport,weather     # exactly these
$ npx -y swissyphus --preset legal --modules fx     # combinable
$ npx -y swissyphus --list-modules                  # everything, with tool counts

  






  

    

      

        
Optional keys

        
None needed. Two add depth.

      

      
Without them, those tools explain how to get one. Pass them through your client’s env block.

    

    

      
OPENTRANSPORTDATA_API_KEYUnlocks get_transport_disruptions and get_realtime_delays. Free at opentransportdata.swiss.

      
ZEFIX_USER / ZEFIX_PASSThe official ZefixPublicREST API for companies; a keyless back-end is used otherwise. Issued by the Federal Office of Justice.

    


{ "command": "npx", "args": ["-y", "swissyphus"], "env": { "OPENTRANSPORTDATA_API_KEY": "…" } }

  






  

    

      
HTTP & Docker

      
Serve REST and remote MCP

      
The same tools over HTTP, generated from the same schemas. Images are multi-arch (amd64, arm64) on Node 24 LTS Alpine, run as a non-root user with a HEALTHCHECK against /v1/health, and shut down gracefully on SIGTERM.

      
Keys and the last-known-good store live under /app/data. Set ADMIN_TOKEN (32+ characters) to enable /v1/admin/*. Production setup with automatic TLS: deploy/.

    

    

      

        
TERMINAL


npx -y swissyphus --http --port 8000                                  # REST + remote MCP

docker run -p 8000:8000 ghcr.io/cwellbournewood/swissyphus             # HTTP
docker run -i --rm ghcr.io/cwellbournewood/swissyphus --stdio          # MCP stdio
docker run -p 8000:8000 ghcr.io/cwellbournewood/swissyphus --http --preset hosted

      

    

  






  

    

      
Verify

      
Is it healthy?

      
The doctor probes every upstream source and prints its status and latency. Agents get the same view from check_source_health, so when a source is down they see it instead of guessing. A nightly canary runs against every live source too.


$ npx -y swissyphus doctor
✓ status and latency for every upstream source
$ npx -y swissyphus --version

    

    

      
Troubleshooting

      

        
CONNECTION_CLOSED or “failed to reconnect”
The server exited before the MCP handshake. Most often the client runs an older Node than your shell: check the node on the client’s PATH is 20 or newer.

        
Corporate proxy or TLS inspection
Set NODE_EXTRA_CA_CERTS to your CA bundle in the server’s env.

        
A tool says the source is unavailable
That’s upstream, not you. Run the doctor. When it has one, Swissyphus serves the last good answer, marked cache_status: "stale".

        
The first sanctions search says the list is loading
The SECO list is a 43 MB download from a slow server. Ask again in a minute; it is then cached for 6 hours. Hosted deployments load it at start-up.

        
Too many tools in context
Use a preset or an explicit --modules list. --preset discovery keeps 7 tools loaded and still reaches everything through call_tool.
