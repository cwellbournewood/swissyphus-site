API reference · v1

MCP and REST.
Same 151 tools.

The server that runs locally over stdio also serves HTTP: a REST API, an OpenAPI 3.1 spec and a remote MCP endpoint, all generated from the same tool schemas. Typed JSON, RFC 9457 errors, CORS on, rate-limit headers everywhere.

Run it

$npx -y swissyphus --http --port 8000

Base URL

http://localhost:8000/v1

Remote MCP

POST /mcp · Streamable HTTP, stateless

Playground

Pick a tool.
Call it any way.

The same call as cURL, MCP JSON-RPC or fetch, next to the envelope it returns. Values are illustrative; the shape is exact.

Endpoints

        
Core routes

      

      
Every tool maps to a predictable path. GET with query parameters, POST with a JSON body for anything more complex.

    

    

      
GET/v1/toolsTool catalogue with input schemas.

      
GET/v1/tools/{name}?…Call any tool with query parameters.

      
POST/v1/tools/{name}Call a tool with a JSON body.

      
GET/v1/sourcesLicence and source register for all 66 sources.

      
GET/v1/healthLiveness.

      
GET/v1/health/sourcesUpstream source health (cached snapshot).

      
POST/v1/keysCreate a free API key from an email address. Shown once.

      
GET/v1/usageYour metered usage (with a key).

      
DEL/v1/keysPermanent erasure of the key, email and usage history.

      
GET/openapi.jsonOpenAPI 3.1, including the Envelope schema.

      
GET/privacyPrivacy notice (Swiss nFADP).

      
POST/mcpRemote MCP over Streamable HTTP, stateless.

    

  






  

    

      
Response envelope

      
Data, plus where it came from

      
Every successful response carries a source object (name, operator, URL, licence, attribution), the retrieval time, the publisher’s own timestamp, the cache status and the upstream requests behind the answer. MCP and REST return the same envelope.


{
  "data": { … },
  "source": {
    "name": "…", "operator": "…", "url": "…",
    "licence": "…", "attribution": "© …"
  },
  "retrieved_at": "ISO 8601",
  "data_as_of": "publisher timestamp | null",
  "cache_status": "hit | miss | stale | computed",
  "provenance": { "upstream": [ { "url", "cache_status", "retrieved_at" } ] }
}

    

    

      
Errors · RFC 9457

      
Problems you can switch on

      
Returned as application/problem+json.

      

        
400
invalid parameters
A parameter failed schema validation.

        
404
no results
Unknown tool, or the source has no data for the query.

        
413
body too large
Over SWISSYPHUS_MAX_BODY_BYTES (1 MiB by default).

        
422
rejected by the tool
The parameters are well-formed, but the tool rejected the input.

        
429
rate limited
Over your tier’s limit; the RateLimit-* headers say when to retry.

        
503
source unavailable
An upstream source is down and no last good answer exists. See /v1/health/sources.

      

    

  






  

    

      

        
Keys & tiers

        
Local: no key, ever.
Hosted: tiered.

        METERING ON · BILLING IS UP TO THE OPERATOR
      

      
An HTTP deployment enforces per-IP limits for anonymous callers and per-key limits and quotas for key holders. Keys work on REST and on POST /mcp, as Authorization: Bearer, X-API-Key or ?api_key=, and are stored only as a SHA-256 hash.

GET A KEY · USE IT · CHECK USAGE


curl -X POST https://your-host/v1/keys -d '{"email":"you@example.com"}'        # → sy_live_… (shown once)
curl -H "Authorization: Bearer sy_live_…" "https://your-host/v1/tools/get_weather?plz=8001"
curl -H "Authorization: Bearer sy_live_…" https://your-host/v1/usage
curl -X DELETE -H "Authorization: Bearer sy_live_…" https://your-host/v1/keys  # permanent erasure

    

  






  

    
Conventions

    

      
AUTHNone locally. Hosted tiers take a Bearer token, X-API-Key or ?api_key=.

      
RATE LIMITSStandard RateLimit-* headers on every response.

      
CACHINGPer-source TTLs, circuit breakers and a last-known-good store; cache_status says which answer you got.

      
CORSEnabled, so you can call it straight from the browser.

      
COORDINATESWGS84 and LV95 throughout; coords converts offline with cm accuracy.

      
PRIVACYSwiss nFADP: privacy notice, records of processing and breach response ship with the server.

      
SCHEMASOne schema per tool generates MCP, REST, OpenAPI and tools.schema.json.

      
VERSIONINGSemantic versioning. Tool names, parameters, the envelope and REST paths change incompatibly only in a major version.
